# FocusWeek｜考试复习规划与专注工作台

> 先回答“下一场考试是什么、还剩多久、现在该复习什么”，再开始计时。

[查看仓库](https://github.com/galjay/focusweek)

## 核心工作流

**录入考试 → 自动排序 → 聚焦下一场 → 开始专注 → 记录今日完成情况**

### 考试安排

- 新增、编辑、删除考试，按时间自动排序。
- 自动识别已结束考试，并将下一场未结束考试提升为主倒计时。
- 根据剩余时间切换展示：超过 24 小时显示天/小时，24 小时内显示小时/分钟，1 小时内显示分钟。
- 倒计时到点后进入已完成状态，下一场考试接管主倒计时。
- 时间轴保留已结束考试，帮助用户查看完整安排。

### 专注与反馈

- 默认 25 分钟专注 / 5 分钟休息，可自定义时长。
- 支持开始、暂停、重置和阶段完成提示音。
- 今日记录保存完成周期数和专注分钟数，刷新后仍保留。
- 提供雨声、咖啡馆、森林、海浪四种随项目发布的本地 OGG 环境音，可切换、开关和调节音量。

## AI / Codex 与产品本人的分工

**产品本人负责：**

- 明确考试周用户场景、核心问题和 MVP 边界。
- 决定“考试优先、单页工作台、下一步行动”这一产品方向。
- 设计考试状态、倒计时切换、专注反馈和验收标准。
- 通过真实考试安排进行验收，并根据使用体验提出迭代。

**AI / Codex 负责：**

- 将 PRD 拆成信息架构、状态逻辑、交互边界和可执行代码。
- 辅助完成考试 CRUD、倒计时状态切换、专注计时、Web Audio、响应式布局和 localStorage 数据流。
- 根据验收清单修复边界问题，并补充项目文档和发布流程。

项目不是“用户独立手写全部代码”的证明，而是用户负责产品决策和验收，AI 辅助完成工程实现与迭代的实践。

## 隐私与数据边界

- 所有考试和专注记录只保存在当前浏览器的 `localStorage`。
- 无账号、无后端、无数据上传。
- 环境音随项目发布，不依赖运行时第三方音频地址。
- 初次打开会生成 3 场相对当前时间的示例考试，便于立即看到完整状态；用户可以编辑或删除。

## 当前限制

- 专注周期暂未和具体科目绑定，不能按科目累计复习时长。
- 数据只在当前浏览器中保存，不支持账号同步、跨设备访问、云端备份或多人协作。
- 倒计时和今日统计依赖浏览器时间与本地存储，清理浏览器数据会丢失记录。
- 当前没有已验证的公开在线 Demo；GitHub Pages 需要实际完成仓库设置和部署验收。

## 验证清单

建议用一组真实考试安排重新验收：

1. 录入至少 3 场真实考试，确认按时间排序且下一场考试突出显示。
2. 将一场考试设置为距离当前超过 24 小时、23 小时和 40 分钟，确认倒计时格式与状态标签切换。
3. 将一场考试设置为过去时间，确认它进入已完成状态，下一场考试接管主倒计时。
4. 新增、编辑、删除后刷新页面，确认安排仍然存在。
5. 将专注时长临时改为 1 分钟，完成一轮后确认周期数和专注分钟数增加，刷新后统计仍保留。
6. 依次开启四种环境音，确认切换、音量和关闭状态正常，并检查浏览器 Console 无未处理错误。

## 下一步验证

不要只用首次打开的示例考试截图。下一轮应使用用户自己的真实考试日期，记录从打开页面到开始第一轮专注所需时间，并观察用户是否能在几秒内回答：

- 下一场考试是什么？
- 还剩多久？
- 现在应该做什么？

如果仍需要额外计算或翻找信息，下一轮应优先优化首页层级，而不是继续增加功能。
