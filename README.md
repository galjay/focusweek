# FocusWeek · 考试复习规划与专注工作台

一个面向大学生考试周和短期备考场景的本地优先 Web 工具。它不把“计时器”当作首页主角，而是先回答最重要的问题：下一场考试是什么、还剩多久、现在应该复习什么。

## 项目背景与用户痛点

考试周里，用户往往同时面对多门考试、不同时间点和有限的复习时间。真正让人焦虑的不是缺少一个番茄钟，而是打开学习工具后依然不知道下一步应该把时间交给哪门课。

FocusWeek 用一个单页深色工作台把考试安排、最近一场倒计时、复习时间轴、专注计时和今日记录放到同一屏，减少在多个应用之间切换的认知成本。

## MVP 核心功能

- 新增、编辑、删除考试；考试按时间自动排序。
- 自动识别已结束考试，并将下一场未结束考试提升为主倒计时。
- 根据剩余时间切换展示状态：超过 24 小时显示“天 + 小时”，24 小时内显示“小时 + 分钟”，1 小时内显示分钟；倒计时到点自动进入已完成状态。
- 未来考试时间轴，突出下一场考试，已结束考试保留在时间轴中但不再占用主倒计时。
- 默认 25 分钟专注 / 5 分钟休息，可自定义时长；支持开始、暂停、重置、阶段完成提示音。
- 环境音：雨声、咖啡馆、森林、海浪四种本地 OGG 音轨，可开启/关闭、切换音色和调节音量；音频会循环播放，不依赖运行时第三方地址。
- 今日完成周期数与总专注分钟数持久化，刷新页面后仍然保留。
- 所有考试和专注记录只使用浏览器 `localStorage`，无账号、无后端、无数据上传。

## 设计思路

视觉上采用“深色夜间工作台 + 紫色主倒计时”的方向：

1. 首页第一视觉区域只放下一场考试和剩余时间，让用户几秒内获得行动线索。
2. 时间轴承担“全局安排”，专注计时承担“此刻行动”，今日专注承担“完成反馈”。三者分别回答不同层级的问题。
3. 使用轻量状态标签区分正常、24 小时内、1 小时内和已完成，避免用户需要自己计算时间。
4. 保留足够留白与低对比边框，适合考试周长时间打开；移动端也会自动收拢为单列布局。

## 技术实现

- 原生 ES Modules + Vite，保持依赖最少，方便放入 GitHub 或静态托管。
- `src/main.js`：状态管理、考试 CRUD、倒计时、专注计时、Web Audio、localStorage。
- `src/style.css`：响应式深色工作台 UI，不依赖组件库。
- `public/audio/`：存放随项目发布的本地环境音素材，来源与授权见 [AUDIO_SOURCES.md](./AUDIO_SOURCES.md)。
- `localStorage`：
  - `focusweek:exams` 保存考试数组。
  - `focusweek:focus` 保存专注配置和当日统计。
- 初次打开会写入 3 场相对当前时间生成的示例考试，便于立即看到完整状态；用户可以直接编辑或删除。

## 运行方法

环境要求：Node.js 18+。

```bash
npm install
npm run dev
```

然后打开终端输出的本地地址。生产构建：

```bash
npm run build
npm run preview
```

这个项目是纯静态前端，构建后的 `dist/` 可部署到 GitHub Pages、Netlify、Vercel 等静态托管平台。

## 发布到 GitHub 与 GitHub Pages

### 1. 创建并推送 GitHub 仓库

先在 GitHub 新建一个空仓库，例如 `focusweek`，不要勾选自动生成 README。然后在项目目录执行：

```bash
git init
git add .
git commit -m "feat: build FocusWeek MVP"
git branch -M main
git remote add origin https://github.com/你的用户名/focusweek.git
git push -u origin main
```

也可以使用 GitHub Desktop：选择 `Add existing repository`，选择本项目目录，提交后点击 `Publish repository`。

### 2. 开启 GitHub Pages

项目已经包含 `.github/workflows/deploy.yml`。推送后打开 GitHub 仓库的 `Actions`，等待 `Deploy FocusWeek to GitHub Pages` 完成；第一次使用时，在 `Settings → Pages → Build and deployment` 中将 Source 设为 `GitHub Actions`。

部署完成后，访问：

```text
https://你的用户名.github.io/focusweek/
```

后续每次推送到 `main` 都会自动重新构建和发布。Vite 已配置相对资源路径，`public/audio/` 里的音频在仓库子路径下也能正常加载。

## 验证清单

建议按以下方式快速验收：

1. 新增一场距离当前超过 24 小时的考试，确认主卡片显示“X天 / X小时”。
2. 编辑考试时间为未来 23 小时，确认切换为“X小时 / X分钟”和 urgent 状态。
3. 编辑考试时间为未来 40 分钟，确认切换为“X分钟”和 critical 状态。
4. 编辑考试时间为过去时间，确认它进入已完成状态，并由下一场考试接管主倒计时。
5. 新增、编辑、删除后刷新页面，确认考试安排仍然存在且顺序正确。
6. 启动专注计时，或把专注时长临时改为 1 分钟，完成后确认周期数和专注分钟数增加；刷新后确认今日统计仍保留。
7. 切换雨声、咖啡馆、森林、海浪，拖动音量和开启/关闭开关，确认不需要任何远程音频文件。
8. 打开浏览器开发者工具 Console，确认页面运行过程中没有未处理错误。

## AI 辅助开发角色分工

- 用户：提供完整 PRD、核心产品原则、MVP 边界和验收标准，决定“考试优先、单页深色工作台”的产品方向。
- AI：将 PRD 拆分为信息架构、状态逻辑、交互边界与可执行代码；实现本地优先数据流、时间状态切换、响应式布局、验证清单和项目文档。
- 验收协作：围绕超过 24 小时、24 小时内、1 小时内、考试结束自动切换，以及刷新持久化场景进行检查，并根据检查结果修复问题。

项目不是由用户独立手写全部代码，而是由用户提供产品决策与验收标准，AI 辅助完成工程实现与验证。

## 后续计划（MVP 之后）

第二阶段再考虑将专注周期与具体科目绑定，并按科目累计复习分钟数。该能力暂未放入 MVP，避免首页信息过载，也避免在还没有稳定的考试—专注基础闭环时增加复杂统计。
